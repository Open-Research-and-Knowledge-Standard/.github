# Security Policy

## Report a vulnerability privately

Use GitHub private vulnerability reporting in the affected repository:

1. Open the repository's **Security** tab.
2. Select **Advisories**.
3. Select **Report a vulnerability**.

Do not include vulnerability details, exploit material, credentials, private
data, or sensitive logs in a public issue, pull request, discussion, commit,
or fork.

If the affected repository does not offer private vulnerability reporting,
open a non-sensitive issue in that repository asking the maintainer to provide
a private contact path. Include no vulnerability details in that issue.

## What to include

When it is safe to do so, include:

- the affected repository, version, tag, or commit;
- the security boundary and observed impact;
- minimal reproduction steps or a proof of concept;
- prerequisites and relevant environment details;
- suggested mitigations, if known.

Remove secrets, personal data, private research material, and unrelated system
information from every report.

## Handling expectations

ORKS is maintained by one person. Reports are assessed and remediated on a
best-effort basis. No acknowledgement, remediation, disclosure, or release
timeline is guaranteed.

Please allow a reasonable opportunity to investigate before public
disclosure. Do not access data you do not own, degrade services, persist in a
system, or expand testing beyond what is necessary to demonstrate the issue.

There is currently no bug-bounty program and no promise of payment or public
credit. Credit may be offered with the reporter's consent.

## Supported versions

ORKS is in early development and has not published a supported release line.
This policy defines a reporting channel and does not promise security fixes
for any version. A repository-specific policy or release notice overrides
this default.
